# 多线程下载 2.0.1

主工程源码位于仓库的 `extension/`，后续功能开发以此为准。纯 Chrome 扩展，无需运行 CMD，无需 Python、aria2、管理员权限或 Native Messaging 注册。

## 加载（首次约一分钟）

1. 先结束旧版正在进行的下载，再关闭旧版的“自动接管”，避免两个扩展同时接管。
2. 解压 ZIP，把整个文件夹放到长期保留的位置。不要删除或移动它。
3. Chrome 地址栏输入 `chrome://extensions/`，打开右上角“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择包含 `manifest.json` 的 `ChromeParallelDownload` 文件夹；如果使用 GitHub 工程源码，则选择仓库内的 `extension` 文件夹。
5. 打开扩展面板，点击“选择文件夹”，选择并授权你希望使用的下载目录。
6. 刷新此前已打开的下载网页，使即时反馈脚本生效。以后正常点击下载即可，也可右键直链选择“使用多线程下载”。

ZIP 是分发包，不是 Chrome 可直接双击安装的文件。普通 Chrome 的本地扩展应使用上述加载方式；企业策略可能禁止开发者模式。最低 Chrome 116，建议使用当前稳定版。

## 本次改进

- 普通文件链接点击立即提示“已点击下载，正在等待网站响应”；浏览器确认后显示“下载已接收”。复杂网页按钮只能在 Chrome 确认下载后提示。
- 先显示任务和连接状态，不让面板等待引擎响应。纯版没有本机桥接启动、RPC 握手或额外 HEAD 探测；首个 Range GET 同时取数据与探测分段能力。
- 可选 4、8、16、32、64 路并发，默认 8；直接使用 Chrome 网络环境。所选数值是并发请求上限，实际并发取决于剩余分段、浏览器调度和服务器响应；不保证等同数量的独立 TCP 连接，也不保证等于原生版或 PCL 的速度。
- 分段写入用户授权目录中的浏览器临时写入文件，完成后提交最终文件，不把整份大文件拼接到内存或搬运到 C 盘缓存。取消会中止写入并清理本任务的空占位文件，完成或取消后自动清空扩展任务记录。
- 支持同一浏览器会话内暂停、继续、取消、切回 Chrome，同名文件自动编号。遇到文件版本变化会拒绝混合分段。

## 边界与安全

- 多连接需要服务器支持 Range 且提供强 ETag；不满足时使用单连接。无可靠续传标识的单连接任务，点击继续会从头下载。
- 自动接管仅针对普通 HTTP/HTTPS GET 文件，至少 2 MiB 或大小未知。带 Cookie/认证、POST、Blob、无痕任务及危险下载留给 Chrome。右键方式也不会复制登录凭据，带登录或防盗链的链接可能失败。
- 关闭扩展小面板不影响下载。完全退出 Chrome 会中断纯版任务；重新打开后尝试恢复 Chrome 原下载，不能恢复时需在原网页重试。右键发起的任务没有 Chrome 备份，需要重新下载。跨浏览器重启的分片续传不是本版功能。
- Chrome 原下载在接管时保持暂停作为回退，完成后取消。正式文件直接在所选目录中，不会作为新的完成条目加入 Chrome 下载记录。
- 文件夹授权可能需要重新确认；没有权限时不接管。请勿在下载期间手动编辑目标占位文件。
- 权限用于识别下载、显示反馈、访问下载来源和本地保存。只检查是否含认证头，不存储认证值；不向第三方上传链接或文件，不加载远程代码。

## 已验证

Node 引擎测试覆盖分段结果逐字节一致、单连接降级、连接中断重试、暂停/继续、取消清理、ETag 变化和同名文件保护。Chrome for Testing 151 的真实扩展测试覆盖网页点击、后台 Worker、真实浏览器文件句柄写入与 SHA-256 一致性。浏览器自动化使用隔离 OPFS 目录，实际目标文件夹的系统授权仍需用户点击。

普通链接的本地测试点击反馈约 30–40 毫秒（模拟网站首响应延迟 500 毫秒）；这是反馈延迟，不代表公网服务器首字节延迟或速度保证。
